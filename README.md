# SecDrift: Measuring Sector-Conditioned Security Drift in AI-Generated Code

[![Python 3.9+](https://img.shields.io/badge/python-3.9+-blue.svg)](https://www.python.org/downloads/)
[![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)](https://opensource.org/licenses/MIT)

A reproducible benchmark for measuring **sector-conditioned security drift**: whether
conditioning an LLM code-generation prompt on an industry context (e.g., a CISA
critical-infrastructure sector) changes the security of the generated code, relative
to a neutral baseline, when the functional task is held fixed.

## Research question

> Does industry framing systematically change the vulnerability rate of LLM-generated
> code, once the functional task and vulnerability-category composition are accounted for?

## Key finding (short version)

**No statistically significant sector-conditioned drift.** Industry-framed prompts
*appear* slightly more secure (baseline 14.0% vs industry 11.4% flagged-vulnerable),
but the −2.7pp gap is **not significant** (two-tailed Fisher's exact *p* = 0.24) and is
a **vulnerability-category composition artifact**: it lives entirely in two CWEs
(insecure deserialization CWE-502 and path traversal CWE-22) and disappears—​even
slightly reverses—​when they are excluded (+0.4pp, *p* = 1.00).

- **Sector identity is a clean null:** 0 of 8 CISA sectors differ from baseline, with
  or without Bonferroni correction (all |Cohen's *h*| < 0.15).
- **Placebo control:** two *non*-CISA sectors (e-commerce, online education), matched
  for length and specificity, reproduce the CISA industry rate almost exactly
  (10.5% vs 11.4%, *p* = 0.63) — the small pooled pattern reflects generic
  industry-framing specificity, not critical-infrastructure sector identity.
- **What does matter is model choice:** flagged-vulnerable rates span 1.8%–16.1%
  across the models that produced analyzable code.

> **Metric note.** "Vulnerability rate" here is a **static-analysis flag rate** (Bandit
> ∪ Semgrep). It is a proxy that does not establish exploitability; see the paper's
> "Metric scope" and functional-quality sections.

## What's evaluated

- **8 CISA critical-infrastructure sectors:** Communications, Defense, Emergency
  Services, Energy, Financial, Government, Healthcare, Nuclear.
- **9 CWE scenarios:** SQL injection (CWE-89), command injection (CWE-78), insecure
  deserialization (CWE-502), path traversal (CWE-22), weak crypto (CWE-327), XSS
  (CWE-79), hardcoded credentials (CWE-798), weak randomness (CWE-330), improper
  certificate validation (CWE-295).
- **7 LLMs (6 produce analyzable code):** Qwen3 32B, Llama 4 Maverick, Llama 3.3 70B,
  Gemma 3 27B, Mistral Large 3, DeepSeek R1. GPT-OSS 120B is evaluated but excluded
  from vulnerability analysis (0% code-production rate).
- **3 prompt conditions:** `baseline` (neutral), `matched_baseline` (sector
  terminology only — interface preserved), `industry` (full industry framing).
- **5 replicates** per condition at temperature 0.7 → **5,355 evaluations**.

## Installation

```bash
git clone https://github.com/secdrift/secdrift.git
cd secdrift
pip install -e .          # installs the `secdrift` package + CLI
python -m secdrift.cli --help
```

Static-analysis backends (Bandit, Semgrep) are installed as dependencies; no API keys
are needed to reproduce the analysis from the shipped data.

## Reproducing the paper

The evaluation dataset used in the paper ships in the repo:

```
results/latest_run/merged_results_5rep.jsonl   # 5,355 records (main corpus)
results/control_pilot.jsonl                    # 630 records (placebo control)
```

All paper statistics are regenerated by the standalone scripts in `analysis/`, which
read the JSONL directly (no API access required):

```bash
python analysis/cwe_exclusion.py         # RQ1: drift + CWE-exclusion sensitivity (Table: sensitivity)
python analysis/leave_one_cwe_out.py     # leave-one-CWE-out robustness (Table: loo)
python analysis/cramers_v.py             # omnibus Cramer's V (RQ1/RQ2)
python analysis/mixed_effects.py         # mixed-effects logistic regression (Table: mixed)
python analysis/length_confound.py       # prompt-length confound analysis
python analysis/completeness.py          # response completeness (Table: completeness)
python analysis/functional_correctness.py   # Tier-1 static functional quality (Table: functional)
python analysis/functional_exec.py       # Tier-2 sandboxed functional pass@1 (baseline)
python analysis/contract_drift.py        # transformation interface-drift audit
python analysis/analyze_control_pilot.py # placebo-control analysis (Table: control)
python analysis/build_validation_sample.py  # 90-item human-validation sample
python analysis/aggregation_sensitivity.py  # RQ1 robustness: aggregation-rule sensitivity (Bandit AND Semgrep; Bandit@MEDIUM)
python analysis/firth_permutation.py     # RQ1 robustness: Firth + permutation tests on the condition effect
```

Each script applies the paper's **code-only filter** (drop GPT-OSS 120B and any
empty/whitespace generation) and prints the numbers used in the paper. `cwe_exclusion.py`
includes a hard sanity check that reproduces the headline 14.0% / 11.4% / −2.7pp.

Aggregate CSV/JSON outputs are cached in `results/extended_analysis/`.

## Re-running the benchmark (optional, needs model access)

Generation uses AWS Bedrock by default (provider-agnostic adapters also support
OpenAI/Anthropic/OpenAI-compatible endpoints).

```bash
export AWS_REGION=us-east-1          # credentials via AWS CLI / IAM role
python -m secdrift.runner --group paper --replicates 5 \
       --output results/rerun.jsonl
python -m secdrift.analysis results/rerun.jsonl
```

Configure models and groups in `config/models.yaml`; the `paper` group lists the seven
models used in the study.

## The 5-dimension transformation

Industry-framed prompts are built from neutral baselines via a formal transformation
`P_i = T(P_b, S, C)` with five dimensions: **D1** context injection, **D2** terminology
mapping, **D3** stakeholder framing, **D4** use-case grounding, **D5** requirement
preservation. The **matched baseline** applies D2 only, isolating a terminology/framing
effect while preserving the task interface. Pressure signals (urgency, shortcuts,
authority appeals) are explicitly excluded and validated against.

> The full industry prompts are authored as realistic domain requests and do not hold
> the surface interface fixed across conditions; the paper quantifies this **interface
> drift** and treats the baseline-vs-industry contrast accordingly. See
> `analysis/contract_drift.py` and the paper's "Transformation Fidelity" section.
